## 產生資料

```bash
uv run export_for_tableau.py      # churn_mart.csv（Power BI）、churn_dashboard.csv、feature_importance.csv、data_quality.csv
uv run tableau/guide/make_data.py # 更新圖解指南上的數字（data.js）
```

模型檔要先存在（`train_and_save.py` 產生）。Tableau 在 Windows 上，只要複製 3 個檔：

```bash
W="$(wslpath "$(cmd.exe /c 'echo %USERPROFILE%' 2>/dev/null | tr -d '\r')")/Documents/churn_tableau"  # Windows 的「文件」› churn_tableau
mkdir -p "$W"
cp tableau/churn_dashboard.csv tableau/feature_importance.csv tableau/data_quality.csv "$W/"
```

## 6 個儀表板、19 張工作表

除了特徵重要度和資料品質檢核，所有工作表都接 `churn_dashboard` 這一個資料來源，所以能連動。

| 儀表板 | 工作表 | 用作篩選器（點了會篩選整頁） |
|---|---|---|
| 總覽 | KPI 橫幅、各合約類型／付款方式／使用月數／網路服務流失率、各合約月營收 | 四張流失率圖、各合約月營收 |
| 流失因子 | KPI 橫幅、合約×網路服務、合約×使用月數、月費分布、各加值服務數流失率 | 兩張熱圖、月費分布、加值服務數 |
| 客群 | KPI 橫幅、客群輪廓、各客群人數與流失率、實際vs預測流失率 | 客群輪廓、各客群人數與流失率 |
| 風險名單 | 現有客戶 KPI、現有客戶風險分級、高風險挽留名單（+ 合約類型、客群篩選器） | 風險分級；篩選器套用到整頁 |
| 模型驗證 | KPI 橫幅、十分位實際vs預測、特徵重要度（`feature_importance`） | 十分位 |
| 資料檢核 | 資料品質檢核（`data_quality`）+ 指標定義 | — |

## 設計決定

- **一份明細、整頁連動。** 業界 dashboard 的核心是連動：點一張圖的某一組（例如使用月數 0-12 個月），KPI 和其他圖都要變成那群客戶的數字。所以互動的圖全部接同一份客戶層級的明細 `churn_dashboard.csv`，每個儀表板對圖開「用作篩選器」。上一版每張圖各用一個預先彙總好的 CSV，圖之間沒有共同欄位，做不到連動，已經整個換掉。
- **指標在 Tableau 裡彙總，不用計算欄位。** 明細先放好輔助欄：`客戶數` 每列是 1（總計＝人數）、`流失人數` 和 `流失率` 都是 0/1（前者總計、後者把預設彙總設成平均值）、`流失月營收`、`預期流失月營收`、`高風險人數` 每位客戶先算好。`平均使用月數`、`平均月費` 是複本，預設彙總設成平均值，給客群輪廓用。
- **KPI 是數字，在 Tableau 設格式。** KPI 橫幅用「顯示 → 文字表」把幾個度量排成一排（度量名稱 + 度量值）。比例設百分比；金額用「數字（自訂）」、單位百萬、首碼 `$`（不用「貨幣」格式：它會照 Windows 地區設定變成 NT$）。Show Me 做出來的欄名會帶彙總字樣（例如「平均值 流失率」），用「度量名稱 → 別名」改回乾淨的名字。
- **儀表板上不寫結論文字。** 數字寫死在文字裡，資料更新後會跟圖對不上；重點交給圖表本身（排序、顏色）。只有兩處文字：風險名單一行說明名單怎麼選、資料檢核的指標定義。
- **特徵重要度、資料檢核是獨立的資料來源。** 兩者都是模型或資料整體的性質，不該隨篩選改變。
- **一支程式產生全部檔案。** `export_for_tableau.py` 先做 Power BI 用的 `churn_mart.csv`，再從它做出 dashboard 明細；兩份明細的機率、客群完全一樣。分級、十分位、挽留名單都用寫進檔案的 4 位小數機率算，在 Tableau 裡驗算也對得上。
- **排序靠資料，不靠手動。** 月費區間、風險等級照文字排會亂掉，附 `區間排序`、`等級排序` 欄，在排序視窗選「欄位」、彙總選最小值。使用月數分組、加值服務數、風險十分位直接用數字開頭的標籤，字母順序就是正確順序。
- **預測機率是交叉驗證的 out-of-fold 機率**（模型訓練時沒看過那位客戶），所以實際 vs 預測、十分位的比較是公平的。
- **風險名單只看還沒流失的現有客戶。** 分三級：機率 ≥ 50% 高風險、20–50% 中風險、< 20% 低風險，全體客戶在這三級的實際流失率約 71% / 34% / 4%。名單（`挽留名單`＝是）是每種合約各取機率最高的 100 位：全體的前幾百名都是同一種客戶（月約、光纖、電子支票、剛加入），分合約取才看得到長約裡也有人要走。
- **客戶編號加上 `C` 開頭。** 全是數字的話，Tableau 會把它當成數值拿去加總。
- **特徵重要度用 LightGBM 的 gain。** one-hot 欄位加總回原本的欄位，換算成占比。
